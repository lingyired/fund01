## 一、为什么要引入小倍养基

### 旧方案的痛点

| 问题 | 旧方案 | 小倍方案 |
|---|---|---|
| 板块标签 | 自研 5 级打分，常给粗行业（"医药生物"）或自造词（"国产芯片"） | 直接取运营精选的 `relatedIndustryV2`，标签跟支付宝/雪球一致 |
| 实时估值 | 东财/fund123 盘中估值，偶尔偏差大 | 小倍有自己的 `dailyYield` 口径 |
| 重仓明细 | 东财 f129 概念 + 简称投票，粒度粗 | 小倍直接给十大持仓 + 占比 + 较上季变化 |
| 板块排行 | 东财 `clist/get`，排行规则不透明 | 小倍热搜榜/旧行业榜，按热度/规模排序 |

### 核心设计原则

> **小倍优先 → 失败降级**。本地多信号打分（5 维）和小倍实时估值（`dailyYield`）同时存在，小倍能取到就用，取不到不影响原有链路。

## 二、小倍养基 API 总览

### 2.1 HTTP 封装：`xiaobeiApiPost`

```javascript
// server/src/services/fund.js L815
async function xiaobeiApiPost(path, code, {allowCodes = [200]} = {}) {
  const padded = String(code || '').padStart(6, '0')
  const res = await axios.post(
    `https://api.xiaobeiyangji.com/yangji-api/api/${path}`,
    { code: padded, version: XIAOBEI_VERSION, clientType: 'APP' },   // ← 见下方版本表
    { timeout: 12000, headers: { 'User-Agent': UA, 'Content-Type': 'application/json' } }
  )
  // 402：部分 QDII 有资产配置但无重仓明细，仍视为成功
  if (res.status !== 200 || !allowCodes.includes(res.data?.code)) return null
  return res.data?.data ?? null
}
```

| 参数 | 说明 |
|---|---|
| `code` | 6 位基金代码，不足 6 位左补零 |
| `version` | **必须 ≥ `3.9.5`**，实测用 `4.2.1` 有效（wzk 的 `3.8.7.0` 已失效，见勘误） |
| `clientType` | `APP` |
| `timeout` | 12 秒 |
| `allowCodes` | 默认 `[200]`，QDII 重仓允许 `[200, 402]` |

#### 版本号门槛实测（2026-09-15，`get-fund-detail-v310`）

| `version` | 005698 (QDII) | 005827 (境内) | 161725 (境内) |
|---|---|---|---|
| `3.8.7.0` | **无 `dailyYield` 字段** | **无字段** | **无字段** |
| `3.8.9.0` | **无字段** | **无字段** | **无字段** |
| `3.9.0` | **无字段** | **无字段** | **无字段** |
| `3.9.5` | −2.08% | −0.01% | −0.46% |
| `4.0.0` / `4.2.1` | −2.08% | −0.01% | −0.46% |

> 注意是**字段不存在**，不是值为 `null`。所以 `Number(data.dailyYield)` → `NaN` → 被当成「无估值」，
> 静默降级到 fallback 源，**不会报错、日志也看不出来**。这是最容易漏掉的一类故障。

### 2.2 用到的 4 个接口

| 接口 | 用途 | 返回值关键字段 |
|---|---|---|
| `get-fund-detail-v310` | **实时估值 + 板块标签 + 板块涨跌 + 基本信息** | `dailyYield`、`relatedIndustryV2[]`、`name`、`investType`、`isDelayFund` |
| `get-net-worth-es` | **盘中估值分时**（见 §2.3） | 421 个 `{date, update, change}` 点 |
| `get-fund-heavy-stock` | **十大重仓股** | `heavyStockList[].name` / `rate` / `rateChange` |
| `get-fund-stock` | **全部持仓（含权重）** | `stockList[].name` / `rate`（Q4 才有） |

> 同一 `get-fund-detail-v310` 接口同时返回实时估值、板块标签和板块涨跌，是**核心接口**。

### 2.3 `get-net-worth-es` — 盘中估值分时

body：

```json
{"code":"005698","version":"3.8.9.0","dataResources":"4","dataSourceSwitch":true,"clientType":"APP"}
```

> 注意这个接口反而要继续用 `3.8.9.0`。

**末点 `change` == `dailyYield`** —— 实测六只 QDII 逐只吻合（005698 末点 −0.0208 = `dailyYield` −0.0208；
012922 末点 −0.0476 = `dailyYield` −0.0476）。也就是说 `dailyYield` 不是独立算的，
**它就是这条分时曲线最后一个点**。

点时分布（美股 QDII，421 个点）：

| | 首点 | 末点 |
|---|---|---|
| 北京时间 | 21:30 | **次日 04:30** |
| 行内 `date` 字段 | `2026-09-14` | `2026-09-15`（跨自然日） |

→ A 股白天不存在属于「今日」的点。对照：港股 QDII / 境内基金的点是当天 09:1x → 当前时刻，跟着 A 股走。

### 2.4 关联板块日收益率（小倍 App 持仓列表那一列）

`relatedIndustryV2` 不只有标签，还带**板块当日涨跌幅**：

```json
{
  "themeName": "海外科技",
  "themeType": "ZS-YC",
  "indexCode": ".NDXT",
  "mappingCode": ".NDXT",
  "extraCode": ".NDXT",
  "sectorCode": "XB1109",
  "type": "USA",
  "openingTime": ["22:30", "05:00"],
  "timeLine": [["21:30","00:45"],["00:45","04:00"]],
  "factor": 1,
  "isTrackingSectorTrend": true,
  "from": "custom",
  "updateBy": "admin",
  "change": -0.0075177
}
```

`change` × `factor` = 板块日收益率（−0.7518%）。**这就是小倍 App 持仓列表「关联板块」列的数字。**

#### ⚠️ 必须用 V2

同一个响应里 `relatedIndustry`（V1）结构一模一样，但 **`change` 恒为 `0`**，也没有 `timeLine` / `factor`。
V1 看起来「字段齐全」，值却是死的 —— 这是最容易误判的地方。

App 账户顶部「当日盈亏」= **Σ(持仓市值 × `dailyYield`)**，实测六只精确到分：

| 代码 | 市值 | `dailyYield` | 当日盈亏 |
|---|---|---|---|
| 100050 | 5,274.95 | −0.0938% | −4.95 |
| 012922 | 5,596.57 | −4.7600% | −266.40 |
| 005698 | 19,388.30 | −2.0800% | −403.28 |
| 022184 | 2,580.43 | −2.3600% | −60.90 |
| 016532 | 12,126.66 | −0.8916% | −108.12 |
| 040046 | 9,407.93 | −0.8916% | −83.88 |

对照：按板块口径算只有 −378.59，对不上。

**但这只出现在账户层。** 持仓列表里单只的「当日收益」单元格对六只 QDII **全部显示 `--`**，
尽管后端有值、聚合层也在用 → 是**展示层刻意不下发单只**，不是取数失败。
（QDII 与境内基金在 `get-fund-detail-v310` 里**唯一的字段差异就是 `isDelayFund`**，
QDII 为 `true`、境内为 `null`；境内另有独有键 `castAdvLink`。）

#### 取数字的两种途径

**路线 A：直接取小倍（与 App 100% 一致）**

```
POST get-fund-detail-v310  →  data.relatedIndustryV2[].change × factor
```

- 附带 `themeName` / `indexCode` / `openingTime` / `type`（`USA` | `A`）/ `timeLine`
- **没有批量接口**。试过 24 个候选路径，只有 `get-industry-fund` 存在（返回 `400 缺少参数`，
  参数名未探明）；`get-industry-list` 等其余全部 404。只能一只基金一次请求。
- 独有价值 = **映射表**（哪只基金 → 哪个板块），这是小倍人工运营的私有数据（`updateBy: "admin"`）

**路线 B：绕开小倍，自己算（可批量）**

| 小倍板块 | 小倍 `indexCode` | 公开代码 | 实测（对 09-14 美股场次） |
|---|---|---|---|
| 纳指100 | `100.NDX100` | 东财 `100.NDX100` | −0.82%（小倍 −0.8216%） |
| 海外科技 | `.NDXT` | **新浪 `gb_ndxt`**（东财**无**此代码） | −0.75%（小倍 −0.7518%） |
| 全球精选 | `251.NQGS` | 东财 `251.NQGS` | −0.56%（小倍 −0.5641%） |
| 海外债 | `107.AGG` | 东财 `107.AGG`（美国全债市ETF-iShares） | −0.09%（小倍 −0.0938%） |

三个坑：

1. 东财**必须走 `push2delay.eastmoney.com`**。`push2` / `1.push2` / `82.push2` / `push2his`
   实测均 `http=000` 不可达。
2. 东财 **`f3` 是「百分点 × 100」**（`-82` → −0.82%），且**只有 2 位精度**。
   要 4 位得用 `f2`(最新价) 与 `f18`(昨收) 自己算。
3. 新浪 `hq.sinajs.cn` 响应是 **GBK**，需 `decode('gbk')`，并带 `Referer: https://finance.sina.com.cn/`。

> **这些板块值统一在北京 04:00 前后定稿**（美股收盘），白天一整天不再变化
> —— 六只的行情时间全是 `2026-09-15 04:00`，且 12:53 抓到的小倍值与用户 12:55:46 在 App 看到的一致。
> 所以**按日缓存即可**，不需要进 60s / 600s 那套刷新循环。

#### 分清两个「板块」概念

| 概念 | 含义 | 变化频率 |
|---|---|---|
| 板块**标签**（`themeName`） | 这只基金属于哪个主题 | 季度级（跟随持仓披露） |
| 板块**涨跌**（`change`） | 该主题指数当日的涨跌幅 | **按日**（美股场次北京 04:00 定稿） |

wzk 已对两者分别建缓存（标签 3 天、估值 60s），路线 A 落地时**涨跌应独立成「按日」层**，
不要跟 `dailyYield` 的 60s 混用。

## 三、实时估值链路（重点）

### 3.1 数据流总览

```
┌─────────────────────────────────────────────────┐
│  小倍 API: get-fund-detail-v310                   │
│  返回: dailyYield（小数，如 0.0268）              │
└─────────────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────────────┐
│  parseXiaobeiDailyYield(data)                    │
│  转换: 0.0268 → 2.68（百分数，保留两位）        │
└─────────────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────────────┐
│  放入 xiaobeiDetailCache（60s TTL）              │
│  供: peekXiaobeiRealtimePercents（只读缓存）     │
│      getXiaobeiRealtimePercents（批量拉取）      │
└─────────────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────────────┐
│  resolveFundQuote(code, name, fund123Data)       │
│  realtimePercent = 小倍估值 或 fallback          │
│  输出到: /api/funds/quotes → 前端 FundQuoteRow   │
└─────────────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────────────┐
│  web 前端: FundTrendDialog                       │
│  展示: "实时涨跌 +2.68%" 徽章                     │
└─────────────────────────────────────────────────┘
```

### 3.2 关键函数：parseXiaobeiDailyYield

```javascript
// server/src/services/fund.js L1394
function parseXiaobeiDailyYield(data) {
  const raw = Number(data?.dailyYield ?? data?.changeRate)
  if (!Number.isFinite(raw)) return null
  return Math.round(raw * 10000) / 100  // 0.0268 → 2.68
}
```

| 字段 | 含义 | 示例 |
|---|---|---|
| `dailyYield` | **盘中实时估值**（小数） | `0.0268` → `2.68%` |
| `changeRate` | 热搜榜用的涨跌（**开盘常为空**） | **不能当同源！** |

> ⚠️ **重要**：`changeRate` 只在小倍热搜榜接口里有意义，和 `dailyYield` 不是同一口径。代码里用 `??` 做兜底，但注释明确警告"开盘常为空，不能当同源"。

### 3.3 缓存策略

```javascript
// server/src/services/fund.js L1364-L1391
const XIAOBEI_DETAIL_TTL_MS = 60 * 1000        // 60 秒（盘中刷新频率）
const xiaobeiDetailCache = new Map()            // 内存缓存
const xiaobeiDetailInflight = new Map()         // 防并发重入

async function loadXiaobeiFundDetail(code) {
  // 1. 缓存命中且未过期 → 直接返回
  // 2. 有正在进行的请求 → 复用 Promise（防重入）
  // 3. 发起新请求 → 成功后写入缓存 + 清理 inflight
}
```

| 策略 | 说明 |
|---|---|
| **TTL 60 秒** | 盘中每 60 秒刷新一次实时估值 |
| **内存缓存** | 重启 server 丢失（非持久化） |
| **防重入** | 同一 code 同时只有一个请求在飞 |
| **批量并发** | `getXiaobeiRealtimePercents` 按 chunk=10 分批并发 |

### 3.4 批量接口：getXiaobeiRealtimePercents

```javascript
    const settled = await Promise.allSettled(

    )
    // 逐个 parseXiaobeiDailyYield，放入 Map<code, percent>
  }

```


## 四、板块标签链路（与实时估值共享缓存）

### 4.1 同一接口，两个用途

`get-fund-detail-v310` 同时返回：
- `dailyYield` → 实时估值
- `relatedIndustryV2` → 板块标签

```javascript
// server/src/services/fund.js L1460-L1466
const data = await loadXiaobeiFundDetail(code)  // 共享 60s 缓存
const rows = Array.isArray(data.relatedIndustryV2)
  ? data.relatedIndustryV2
  : Array.isArray(data.relatedIndustry)  // 兼容旧字段
    ? data.relatedIndustry
    : []
```

> ⚠️ **这个 V1 兜底只对「标签」安全，对「涨跌」不安全**：V1 的 `change` 恒为 `0`（见 §2.4）。
> 如果同时要 `themeName` 和 `change`，**不能**在 V1 上兜底 —— 会静默拿到 0% 板块涨跌。
> 此时应判 `relatedIndustryV2` 缺失即整体视为无板块数据。

### 4.2 板块缓存策略不同

```javascript
// server/src/services/fund.js L1365
const XIAOBEI_SECTOR_TTL_MS = 3 * 24 * 60 * 60 * 1000  // 3 天
const xiaobeiSectorCache = new Map()
```

| 字段 | TTL | 原因 |
|---|---|---|
| `dailyYield`（实时估值） | 60 秒 | 盘中变化快 |
| `relatedIndustryV2`（板块标签） | 3 天 | 板块变化慢，减少请求 |

**注意**：虽然共享 `loadXiaobeiFundDetail` 的 60s 短缓存，但板块标签有独立的 3 天缓存层，从短缓存结果里进一步提取并缓存。

### 4.3 标签清洗规则

```javascript
// server/src/services/fund.js L1470-L1483
for (const row of rows) {
  const name = String(row?.themeName || '').trim()
  if (!name || name === '--' || name === '-' || seen.has(name)) continue
  if (name.length > 16) continue  // 超长截断
  seen.add(name)
  items.push({
    name,
    sectorCode: String(row?.sectorCode || '').trim(),      // 用于跳转
    mappingCode: String(row?.mappingCode || '').trim(),    // 映射到行情
  })
}
```

小倍侧已经做过人工运营精选，所以 wzk 只做了**极简清洗**：去空、去占位、去重、截断超长。

### 4.4 降级策略

```javascript
const xiaobei = await fetchXiaobeiSectorItems(code)
if (xiaobei.length) return xiaobei  // 小倍优先
```

## 五、重仓明细链路

### 5.1 两个接口联调

```javascript
// server/src/services/fund.js L986-L1028
async function fetchXiaobeiHoldingsBundle(code) {
  const [heavy, stock, asset] = await Promise.all([
    xiaobeiApiPost('get-fund-heavy-stock', code),      // 十大重仓
    xiaobeiApiPost('get-fund-stock', code, {allowCodes: [200, 402]}), // 全部持仓
    xiaobeiApiPost('get-fund-detail-v310', code),      // 资产配置
  ])
  return {
    holdings: heavy?.heavyStockList?.map(mapXiaobeiHeavyRow),
    allocation: mapXiaobeiAllocation(asset || {}),
    source: holdings.length ? 'xiaobei' : '',
  }
}
```

| `get-fund-stock` | 全部持仓（Q4 才有权重） | 可能 402 |
| `get-fund-detail-v310` | 资产配置（股票/债券/现金比例） | 正常 |

> QDII 部分接口返回 402（有资产配置但无重仓明细），代码里 `allowCodes: [200, 402]` 兼容。

## 七、关键设计决策

### 7.1 为什么 `dailyYield` 和 `changeRate` 不能混用？

```javascript
// server/src/services/fund.js L1393 注释
/** dailyYield 为小数（0.0268 → 2.68）；
 *  热搜基金 changeRate 开盘常为空，不能当同源 */
```

| 字段 | 来源接口 | 盘中可用性 | 用途 |
|---|---|---|---|
| `dailyYield` | `get-fund-detail-v310` | ✅ 持续更新 | **实时估值** |
| `changeRate` | `get-fund-heat-boards` 等热搜接口 | ⚠️ 开盘常为空 | 热搜排序 |

### 7.2 为什么缓存 TTL 是 60 秒？

Server 端行情轮询周期约 30 秒（`goldAlert.js` 金价告警是 30s，基金轮询也是类似频率）。60 秒 TTL 意味着：
- 两次轮询之间（30s）命中缓存
- 超过 60 秒（约 2 次轮询后）刷新数据

这是一个折中：避免每次请求都打接口（限流风险），同时保证盘中数据不太旧。

### 7.3 为什么板块标签缓存 3 天？

板块标签变化频率远低于盘中估值。基金持仓每季度才披露一次（1/4/7/10 月），所以 3 天 TTL 足够。

### 7.4 小倍失败时会不会导致页面白屏？

不会。全链路都有 `try/catch` + fallback：

```javascript
// resolveFundQuote L2261-L2282
try {
  const detail = await loadXiaobeiFundDetail(code)
  realtimePercent = parseXiaobeiDailyYield(detail)
  // ...
} catch {
  // fallback 到 estimateGrowth
}
if (realtimePercent == null && estimateGrowth != null) {
  realtimePercent = round2(estimateGrowth)
}
```

## 十、一句话总结

> **小倍养基通过 `get-fund-detail-v310` 一条接口，同时提供「实时估值（`dailyYield`）」「板块标签（`themeName`）」和「板块日涨跌（`change`）」。Server 端用 60 秒短缓存管理实时估值、3 天缓存管理板块标签，批量并发拉取（chunk=10），失败时无缝降级到东财/fund123 原有数据。前端只在「基金详情弹窗」和「板块热搜列表」展示 `realtimePercent`，自选/持仓列表仍沿用 `resolveDisplayPercent` 决策后的统一涨跌幅。**

**2026-09-15 补充**：`version` 门槛升到 `3.9.5`（旧值 `3.8.7.0` 会让整条链路空转）；
`relatedIndustryV2` 的 `change` 才能拿到板块涨跌（V1 恒为 0）；
板块涨跌按日缓存（美股场次北京 04:00 定稿），不要与 `dailyYield` 的 60s 混用。

### 11.3 先想清楚一件事：数据本身不必绑小倍

路线 A 拿到的 `change` 是**板块指数涨跌**（纳指100 −0.82%），不是基金自己的当日收益。
这组数字**路线 B 用东财 `push2delay` 批量就能拿**，而 Fund01 本来就在用东财（指数面板 / `market.rs`）。

| | 路线 A（小倍） | 路线 B（东财 + 新浪） |
|---|---|---|
| 与 App 一致 | ✅ 逐位一致 | ✅ 同源（板块值就是指数涨跌） |
| 批量 | ❌ 一只一请求 | ✅ 一次可多码 |
| 第三方依赖 | 引入小倍（非官方源） | 已有 |
| 独有价值 | **映射表**（基金 → 板块） | 无映射，需自建 |

**结论**：只想要「板块涨跌数字」→ 走 B，成本低得多。
需要「小倍的板块标签体系」（比自研打分更准）→ 才值得走 A 全量，顺带把涨跌一起拿。
A 的真正不可替代项是**那张映射表**。
