# 检查更新：服务端接入

Fund01 桌面版（Tauri）在打开设置界面时会检查一次是否有新版本。**服务端按平台（macos / windows）分发版本号，客户端零改动**——服务端是 lingai.net 已部署的标准版本检查 API（动态生成 `version.json`，见本文第三节），平台分发只需在配置里加一个映射，无需任何服务端开发，零维护成本。

## 一、客户端行为（了解即可）

- 触发时机：打开设置界面（每次都会检查，结果内存缓存 1 小时，1 小时内重复打开不再请求）。
- 请求地址：`GET https://lingai.net/fund01/version.json?v=1.2.0&os=macos&arch=arm64`，超时 10 秒。`v` 为客户端当前版本号（x.y.z）；`os` = `macos` / `windows`；`arch` = `x64` / `arm64`（**服务端暂未启用 arch，预留**）。**服务端按 `os` 返回对应平台的版本号**（无 `os` / 未知 `os` 时返回默认版本，老客户端天然兼容），同时按 os 统计客户端平台分布。
- 有更新：设置页「关于」区显示「发现新版本 vX.Y.Z」提示条 +「下载新版本」按钮，点击用系统浏览器打开 `downloadUrl`（缺省 fallback 打开项目主页）；`downloadUrl` 存在时另有「前往项目主页」按钮。
- 无更新 / 请求失败 / JSON 非法：完全静默，用户无感知。
- 不支持热更新：不会自动下载 / 安装新版本，只提示「下载新版本」（打开 downloadUrl）与「前往项目主页」。

## 二、JSON 格式

```json
{
  "latestVersion": "1.2.0",
  "homepage": "https://lingai.net/fund01",
  "downloadUrl": "https://lingai.net/fund01/Fund01_1.2.0_arm64.dmg"
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `latestVersion` | 是 | 最新已发布版本号，**必须为纯 `x.y.z` 三段数字**（如 `1.2.0`）。非数字或带后缀（如 `1.2.0-beta`）会被客户端判为「无更新」。发布新版本时同步更新。**服务端可配置 `latestVersions.{macos|windows}` 按平台返回不同版本号**（配置了且请求带对应 `os` 时优先返回它；不带 `os` 的请求永远返回 `latestVersion`）。 |
| `homepage` | 否 | 「前往项目主页」按钮的跳转地址，缺省时客户端用 `https://lingai.net/fund01` 兜底。 |
| `downloadUrl` | 否 | 新版本下载地址。「下载新版本」按钮优先打开该地址；**缺省（不填）时 fallback 打开 `homepage`**；仅当该字段存在时才显示「前往项目主页」按钮（避免两个按钮指向同一地址）。 |

版本比较规则：按 `x.y.z` 逐段数字比较，仅当远端版本高于当前版本时提示。

## 三、服务端实现（lingai.net 现行方案）

线上 `https://lingai.net/<project>/version.json` 由 Node API（`lingai-api` 服务，端口 8787）**动态生成，
不是静态文件**。仓库在 `lingai.net/api/`（`server.js` + `config.json` + `bump-version.sh`），
部署于服务器 `/www/wwwroot/lingai.net/api`（systemd 常驻，`MemoryMax=128M`），详见 `lingai.net/api/README.md`。

- 客户端始终请求 `https://lingai.net/fund01/version.json` **这一个地址**（带 `?v=&os=` 参数），无需按平台换 URL。
- 服务端按 `os` 参数返回对应版本号；**不带 `os` 的老客户端拿到默认 `latestVersion`，行为与之前完全一致**。
- `config.json` 中对应的配置形态：

```json
{
  "projects": {
    "fund01": {
      "latestVersion": "1.4.0",
      "homepage": "https://lingai.net/fund01",
      "latestVersions": {
        "macos": "1.5.1",
        "windows": "1.4.0"
      }
    }
  }
}
```

> `latestVersions.<os>` 缺失 / 请求无 `os` / `os` 未知 → 一律回退 `latestVersion`，容错无感。
> `arch` 暂未启用；将来要分架构时把 `latestVersions.<os>` 从字符串升级为
> `{ "arm64": "...", "x64": "..." }` 对象即可（服务端已支持），客户端无需改动。

## 四、发布流程（发布新版本时）

1. 修改 `api/config.json` 中对应字段：默认版本改 `latestVersion`；按平台分发改 `latestVersions.<os>`；
2. 走 `bump-version.sh` 一键流程（见下）或手动 `rsync config.json` → `sudo systemctl restart lingai-api`；
3. 验证：浏览器打开 `https://lingai.net/fund01/version.json`（带 `?os=` 验证对应平台）应返回新版本号。

> ⚠️ 本地 `config.json` 有 `fs.watch` 热加载，但 rsync 是「写临时文件 + rename」替换，旧 inode 不触发回调——
> **rsync 推送后必须 `systemctl restart lingai-api`**，否则线上不生效。

### 产物来源约定（2026-08-31 定：正式发布一律用 CI 产物）

- **GitHub Release 的安装包只用 CI 打的 `-ci` 后缀产物**（`.github/workflows/build-release.yml`，
  push `tag v*` 或手动 dispatch 触发，产物上传 artifact 保留 30 天），**不用本机打包产物**。
- 原因：① 可追溯——tag 对应精确 commit，任何人可重现；本机包无法证明是哪个 commit 打的；
  ② 可复现——CI 是 fresh checkout + frozen-lockfile + 固定 toolchain，不带本地未提交改动；
  ③ 签名一致——CI 用 env `APPLE_SIGNING_IDENTITY=Fund01`（GitHub secret 证书导入临时钥匙串）→ 产物
  `Authority=Fund01`；本机 `tauri.conf.json` 固定 `signingIdentity: "-"` → 产物 `Signature=adhoc`
  （signingIdentity 为 `-` 时 tauri 走 ad-hoc；实测 target 与 release-macos 归档均无 Authority 行），
  同一版本号只能保留一种签名来源；
  ④ Windows 唯一来源——Windows 包只能由 CI 构建（MSVC + NSIS），三端统一走 CI 避免两套来源混用。
- 本机打包（`scripts/build-tauri-all.mjs` / `tauri build` / Chrome `pnpm build`）**仅限开发迭代自测与
  自己装**（本机包为 ad-hoc，自装需 `xattr -rd com.apple.quarantine /Applications/Fund01.app`），不进 Release。
- 发布动作：push tag → CI 出三端 `-ci` 产物 → 下载 artifact → `gh release create` 上传（见 v1.5.1 发布链路）。

### lingai.net 版本接口联动（发布新版本时勿漏）

桌面版发布新版本后，**必须**把 `https://lingai.net/fund01/version.json` 的版本号同步为新版本（默认
`latestVersion`，按平台则 `latestVersions.<os>`），否则客户端检查更新仍会指向旧版本。

lingai.net 仓库的 API 服务（`/Users/lingsmbp/Documents/workspace/lingai-server/lingai.net`）提供一键脚本：

```bash
cd /Users/lingsmbp/Documents/workspace/lingai-server/lingai.net
bash api/bump-version.sh fund01 <ver>            # 例：bash api/bump-version.sh fund01 1.5.1
bash api/bump-version.sh fund01 <ver> macos      # 只更新 macOS 分发版本：bump-version.sh fund01 1.5.1 macos
```

脚本自动完成：① 改本地 `api/config.json`（无第三参数 → `latestVersion`；有 → `latestVersions.<os>`）→
② rsync 到服务器（`lingai-vps` ssh 别名，需要 `~/.ssh/config` 可读 + 代理通道可达；本机 10808 代理须在跑）→
③ `sudo systemctl restart lingai-api` → ④ 校验线上 JSON（带 os 时追加 `?os=`）。

验证：

```bash
curl -s https://lingai.net/fund01/version.json            # 应返回默认 "latestVersion": "<ver>"
curl -s "https://lingai.net/fund01/version.json?os=macos" # 应返回 macOS 分发版本
```

> ⚠️ 该操作会改动**线上服务**，需人工确认后执行；agent 环境请勿自动代跑（服务器凭据 / ssh 配置属敏感资源）。
> **此步自 v1.4.0 起一直未执行**：GitHub Release 已建到 **v1.6.0（当前 Latest）**，而线上版本号只有
> v1.4.0 那次同步过 → 运行 1.4.0 及之后版本的客户端都收不到更新提示。
> 执行前请先用上面第一条 `curl` 确认真实线上值（agent 不代查线上状态），再按需补跑 `bump-version.sh`。

## 五、容错约定（服务端无需处理）

- 客户端 10 秒超时，超时 / 网络失败 / 404 / JSON 解析失败 → 静默（不提示、不报错）。
- `latestVersion` 非法（非 `x.y.z` 数字）→ 保守判「无更新」。
- 无 `os` / 未知 `os` / 未配置 `latestVersions` → 服务端一律返回默认 `latestVersion`，客户端照常比较，无感知。
- 缺 `homepage` → 用默认值 `https://lingai.net/fund01`。
