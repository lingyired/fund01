> 状态：已于 2026-08-08 开发（分支 feat/holdings-entry-unify）。
> **2026-08-09 用户决策变更（以本行为准）**：popup 界面**不做**内联新增/修改（D1 回退），一切增改通过 popup 底部「修改持仓」按钮进入设置页操作；D2（统一录入 = 持有金额+持有收益）、D3（显示持有成本）、D4（口径说明）保留。popup 列表仅展示（点击名称看详情），保持界面与代码干净。

## 1. 背景与现状问题

### 1.1 当前三处录入/编辑入口不一致

| 入口 | 位置（代码） | 当前录入字段 | 形态 |
|---|---|---|---|
| 添加持仓 | `OptionsApp.tsx:908` 内联 `FundFormBody` | 基金代码 · 分组 · **金额口径(prev/today)** · **持仓金额** · 成本单价(可选) | 单只、金额主导 |
| 编辑持仓（批量） | `OptionsApp.tsx:938` 区块 + `batchEdit.ts` | 每行 **持有份额** · **成本单价(可选)** | 批量表格、份额主导 |
| 导入持仓 | `OptionsApp.tsx` 导入区块 + `importHoldings.ts` | 金额 / 份额 / 持有收益 三选一 | 批量 JSON |
| popup 点持仓 | `FundList.tsx:447` → `FundDetailDialog.tsx` | 无（纯只读详情） | 只读 |

- **不一致点**：添加用「金额」、编辑用「份额」，两套主字段；且都在设置页，popup 列表点基金只能看、不能改。
- **隐藏事实**：导入模块早已支持「市值 + 持有收益」折算成 `shares + cost`（`fundOps.ts` 优先级 `shares > amount > holdProfit→cost`），只是新增/编辑表单还卡在单一口径。

### 1.2 收益术语混乱

市面上有 持有收益 / 持仓收益 / 累计收益 多个词。经与支付宝、天天基金截图对账确认：
- 支付宝「持有收益」、天天基金列表「持仓收益」= **同一数**（当前市值 − 当前持仓成本）。
- 天天基金列表另列的「持有收益」（第三位）= 当前市值 − **历史累计投入**（含已赎回的已实现部分），**≠** 我们的持有收益。
- Fund01 当前不追踪已实现收益，故「累计收益」恒等于「持有收益」，单列反而迷惑。

### 1.3 参考产品的人体工学

小倍养基、养基宝（百万级用户）列表只露「持有金额 / 昨日收益 / 持仓收益」；AI 截图导入走的也是列表视图。用户的录入应直接复用列表上能看到的数，而非详情页里的成本单价。

---

## 2. 设计目标

1. **列表即可增改**：基于持仓列表、不进详情页，就能新增与修改单只基金。
2. **录入字段统一**：新增与编辑用同一套录入字段。
3. **显示持有成本**：UI 展示「持有成本」（= 持有金额 − 持有收益，精确）。
4. **澄清口径**：在某处告诉用户天天基金「持仓收益」= 我们的「持有收益」，其另列「持有收益」不同。

## 4. 改动内容与原因（逐条）

### 4.1 增改入口从设置页移入 popup 列表内联弹层
- **改什么**：在 `FundList.tsx` 每行加「编辑」入口，点开内联弹层（2 字段）；列表底部加「+ 添加持仓」入口。
- **为什么**：用户盯着基金列表/截图操作最顺手；当前「加/编都在设置页、列表只能看」割裂。详情页保持只读即可。

### 4.2 统一录入字段为「持有金额 + 持有收益」
- **改什么**：新增与编辑弹层都只收这两个字段（+ 金额口径选择器，见 §7）。
- **为什么**：
  - 这两个是列表/截图可见数，用户抄得最顺；
  - 三个头条数字**全部精确录入**：持有金额✅、持有收益✅、持有成本=金额−收益✅；
  - 仅「成本单价」变为派生值（轻微漂移、不展示不录入，对用户无感）。

### 4.3 编辑持仓表格：输入改为「持有金额 + 持有收益」，持有份额 / 成本单价改为只读展示
> **本项含用户最新补充要求**：当前设置页「编辑持仓」表格（`OptionsApp.tsx:938` + `batchEdit.ts`）原本直接编辑「持有份额 + 成本单价」两个输入框。改为：
> - **可编辑列**：持有金额、持有收益（统一录入口径）。
> - **新增只读展示列**：持有份额、成本单价（由持有金额+持有收益实时派生算出，**不允许编辑**），另可加「持有成本」只读列。
- **为什么**：成本单价在 D2 下已是派生值，不应再让用户手填；但把它**展示出来**（只读）能让用户看到录入产出、便于核对，同时杜绝手改份额/成本导致的口径错乱。
- **注意（待确认的解读）**：以上解读为「编辑表格的可编辑单元格换成 金额+收益，份额/成本变为只读列」。若你的本意是「保留现有份额/成本编辑、额外再加两列只读展示」，请告知——但那样与 D2（成本单价降为派生）冲突，不推荐。

### 4.4 UI 显示「持有成本」
- **改什么**：列表行、弹层回显、编辑表格只读列，均展示 持有成本 = 持有金额 − 持有收益。
- **为什么**：用户明确要看到成本；该数在 D2 下精确可得。

### 4.5 持有收益标签修正（「累计收益」→「持有收益」）
- **改什么**：`types.ts` 中 `totalCumPnl` 的展示语义从「累计收益」改为「持有收益」（存储与计算逻辑不变，仅命名/文案对齐）。
- **为什么**：当前代码把「当前市值 − 成本本金」标成「累计收益」，与用户约定的单一持有收益语义不符，且易与天天基金「累计收益」混淆。

### 4.6 天天基金口径说明两处落地
- **改什么**：
  - 列表「持有收益」标签旁加 ℹ️，hover/点击展开说明；
  - 设置页增加「名词说明」区块，写同一段话。
- **文案（定稿）**：
  > 天天基金的「**持仓收益**」= 我们的「持有收益」（当前市值 − 当前持仓成本）。
  > 天天基金列表另列的「**持有收益**」（含已赎回的已实现部分）≠ 我们的持有收益。Fund01 不追踪已实现，只认前者。
- **为什么**：用户在核对截图时极易被天天基金的多词带偏，必须在使用时刻给出对照。

## 5. 数据推导（核心公式，实现时直接复用）

录入 `持有金额(MV)` + `持有收益(P)` + `金额口径 amountBasis`：

```
基准净值  nav       = amountBasis 选「今日」取今净值 / 「昨日」取昨净值
持有份额  shares    = MV ÷ nav
持有成本  costBase  = MV − P
成本单价  costPrice = costBase ÷ shares  =  nav × (1 − P/MV)   // 派生，只读
昨日收益  pnl       = shares × (今净值 − 昨净值)                  // 已有逻辑
持有收益  = P        // 直接录入，精确
持有成本展示 = costBase  // 精确
```

落库始终是 `allocations[group]=shares` + `costs[group]=costPrice`，与现有存储模型完全一致。

## 7. 必须保留 / 注意点

- **金额口径选择器（amountBasis）保留**：截图里的持有金额可能是按昨收或今值算的，需让用户选「按今日/昨日净值」折算份额，否则派生份额会偏。现有 `FundFormBody` 已有该选择器，弹层沿用。
- **成本单价派生漂移无感**：仅在非展示处存在微小偏差，不影响任何用户可见数字（金额/成本/收益均精确）。
- **不单列「累计收益」**：与 D5 一致，避免与持有收益混淆。
- **存储零改动**：`allocations`/`costs` 模型不变，导入/展示逻辑共用，回归风险低。
