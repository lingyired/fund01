# 菜单栏 / 任务栏「历史」项 — 设计

日期：2026-09-16　分支：`feat/menubar-history-row`

## 目标

macOS 菜单栏与 Windows 任务栏新增一个**可选的全局实例「历史」**，一次性展示整个组合的
累计表现，不用点开 popup 才能看到。

它是唯一一个**上下两行内容都可自定义**的实例（默认「名称文字 + 历史收益额」），每行可选的档：

1. 名称文字（仅第一行可选，默认；取 `menubarHistoryLabel`）
2. 历史收益涨跌幅（累计收益率）
3. 历史收益额（累计收益金额）
4. 当前持仓额

两行档位完全独立，允许重复（设成一样就上下显示同一个数，不做去重干预）。

## 数据来源（全部现成，无需新增请求）

`HoldingsSummary`（Rust `model.rs` / TS `holdingsCalc.ts`）已有：

| 展示档 | 字段 | 口径 |
| --- | --- | --- |
| 历史收益额 | `totalCumPnl` | 最新市值 − 成本；未录入成本时为 `null` |
| 历史收益涨跌幅 | `totalCumPnlPercent` | `(市值 − 成本) / 成本 × 100`；未录入成本时为 `null` |
| 当前持仓额 | `totalAmount` | 与 popup 顶部「持仓金额」同一个数（估值期按昨净值×份额、确认期按当日净值×份额） |

三者都已按 `overviewExcludedGroups` 的总览口径聚合（被排除分组不计入），与菜单栏「总览」实例同源。

## 设置项（`AppSettings` 新增 5 个）

| key | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `menubarHistoryEnabled` | `boolean` | `false` | 总开关。关=实例不存在 |
| `menubarHistoryLabel` | `string` | `'历史'` | 第一行的名称文字。trim；空串回落默认；超 8 字符截断。**只在第一行档为 `label` 时显示** |
| `menubarHistoryTopMode` | `MenubarHistorySlotMode` | `'label'` | **第一行**档：`label` / `cumPercent` / `cumAmount` / `holdingAmount` |
| `menubarHistoryMode` | `MenubarHistoryMode` | `'cumAmount'` | **第二行**档：三档数值（**不接受 `label`**，传了判非法回落）。⚠️ 默认值 2026-09-16 由 `cumPercent` 改为 `cumAmount` |
| `menubarHistoryBottomColor` | `string` | `''` | **第二行**自定义色（`#rrggbb`）。**空串 = 未自定义**（按语义取色），故归一化不能在非法时回落到某个具体默认色 |

第一行的自定义色**不**单独设字段，复用分组色表 `menubarGroupColors['__history__']`
（`MENUBAR_HISTORY_KEY`）——历史项与各分组共用同一套上行配色机制，设置页也复用同一组交互。

⚠️ **5 个字段都必须接入「三处白名单」**，缺一处就是运行时静默失效（项目已知坑，2026-09-16 踩过）：
① `portfolioLogic.ts`：`DEFAULT_CONFIG.settings` 默认值 **+** `normalizeConfig` 的 settings 重建对象；
② `fundOps.ts` 的 `updateSettings`（**逐字段 if 白名单**，不是通用 merge）→ 漏这里表现为「点了没反应 / 开关弹回」；
③ `portfolio.rs` 的 `normalize_config` 重建对象（+ `Some(...)` 默认值）+ `model.rs` 字段。

## 实例

- id：`menubar-history`（常量 `INSTANCE_HISTORY`，与 `menubar-overview` 并列）
- 顺序：**排在最前**（历史 → 总览 → 分组 → 未分组）。macOS 可用 ⌘-拖拽调整；Windows 按此顺序。
- 复用两张现有 key 表（新增 `MENUBAR_HISTORY_KEY = '__history__'`）：
  - `menubarGroupColors` → 历史项**第一行**文字自定义色
  - `menubarGroupSides` → 历史项在 Windows 任务栏的停靠侧
  - ⚠️ **不**写 `menubarHiddenGroups`：历史项的隐藏语义就是 `menubarHistoryEnabled = false`
- 开关关闭时实例从 `desired_instances()` 移除 → 真正销毁（与「总览永不销毁」不同，因为关闭状态
  由设置项持久化，无需靠实例存活保留菜单栏位置）。

## 展示规则

两行共用同一个纯函数 `history_row_display(spec, mode, privacy)`（`menubar_common.rs`），
macOS 与 Windows 取同一份结果；`rows_of(...)` 再按实例类型分派（当日收益实例走上行名称 + 下行
`menubarShowAmount`，历史实例走上下两行各自档位）。

```
mode = label                    → spec.top（名称文字），无涨跌语义
mode = holdingAmount            → format_holding_amount(totalAmount)，无涨跌语义
mode = cumAmount  且 totalCumPnl ≠ null        → format_amount(totalCumPnl)，有涨跌语义
mode = cumPercent 且 totalCumPnlPercent ≠ null → format_pct(...)，有涨跌语义
mode = cum*       且对应值为 null（未录入成本） → 回退 format_holding_amount(totalAmount)，无涨跌语义
行情快照未就绪（quote 为 None）               → 显示 "-"，无涨跌语义
```

**颜色**（两行各自独立解析，函数 `resolve_row_style`，两端同款）：

```
① 该行有显式自定义色 → 用它（用户意图优先，即便该行是数值也照用）
② 否则该行有涨跌语义 → 涨跌色（涨红跌绿，沿用 menubarRiseColor / menubarFallColor / menubarFlatColor）
③ 否则 → 该行的兜底色：
     上行 = 全局上行色（menubarTopColor）→ 系统默认色（深浅色自适应）
     下行 = 已解析的上行色（Default 亦随之继承）
```

即：第一行显示数值时未自定义 → 按涨跌取色（与第二行同色系）；显示名称时未自定义 →
走原来的上行颜色链。「当前持仓额」及其回退没有涨跌语义 → 用中性色（跟随上行），
不用红绿（否则会被误读成当日涨跌）。

**隐私模式**（`privacyMode = true`）沿用现有「菜单栏强制百分比」约定（两行各自适用）：

- `cumAmount` → 降级显示 `cumPercent`
- `holdingAmount`（含无成本回退）→ 显示 `****`

**格式化**：新增 `format_holding_amount`（菜单栏/任务栏专用，第 5 套，与既有四套互斥隔离）：
无方向符号，绝对值 ≥ 10 万用 `w` 缩写（整数不带小数），否则四舍五入到整数。

## 空态判定（两端 1:1 铁律）

`menubar_all_hidden`（Rust）/ `isMenubarEmpty`（TS）各加一条：

```
menubarHistoryEnabled == true → 菜单栏非空
```

## 交互

- macOS **⌘-拖出**历史实例 → 直接把 `menubarHistoryEnabled` 置 `false`（等价于在设置页关掉该项），
  不写入 `menubarHiddenGroups`。设置页开关随 config-change 实时同步。
- 右键菜单**不**给历史项挂「隐藏该分组」（与总览口径一致）。
- 点击历史实例 → 跳 popup 的「总览」tab（`popup_tab_for` 映射到 `'all'`）。

## Key 映射

- `group_key_of("menubar-history")` → `'__history__'`（**第一行**自定义色 / Windows 停靠侧；
  第二行颜色走独立字段 `menubarHistoryBottomColor`，不入该表）
- `instance_label("menubar-history")` → 设置里的自定义名称？
  否 —— 恒返回 `'历史'`（日志/菜单文案用固定名，避免用户改名后菜单项文案漂移）。

## 不做的（YAGNI）

- 不做「按分组的历史收益」行（分组实例仍只显示当日收益）
- 不做「第一行留空」档（插件按两行渲染，空上行会留白、高度不收缩，看起来像渲染异常）
- 不做两行档位去重（用户明确要「允许重复」，原样显示更可预期）
- Chrome 扩展不涉及（badge 单行）；设置项只出现在 tauri 的「菜单栏/任务栏」tab

## 验收

1. `pnpm -r typecheck` + `pnpm -r build` + `cargo check --all-targets` + `cargo test --lib` + `guard:shim` 全绿
2. grep 5 个字段名：TS 侧 ≥ 4 处（types 定义、normalize 函数、DEFAULT_CONFIG、normalizeConfig 重建对象）、
   Rust 侧 ≥ 3 处（`model.rs` 字段 + `portfolio.rs` normalize + 重建对象）
3. 单测覆盖：`format_holding_amount` 边界、`history_row_display` 全部分支（四档 × 有无成本 × 隐私开关）、
   上下行同档重复、快照未就绪占位、档位解析白名单（含**第二行拒绝 `label`**）、当日收益路径回归护栏
4. 运行时 smoke（临时 tsx 脚本，跑完即删）：直调 `updateSettings` 断言 5 字段全部能写入并回读，
   且「改其它设置后不回落」（白名单漏接的唯一有效检出手段，typecheck 看不见）
5. 真机：macOS 菜单栏开启后出现最左「历史」项；第一行可切数值档并自动红绿；
   ⌘-拖出后设置页开关自动关闭

## 变更记录

- **2026-09-16 初版**：上行固定名称 + 下行三档（`menubarHistoryMode` 默认 `cumPercent`）。
- **2026-09-16 二次迭代（两行对等）**：用户提出「第一行也应能显示数值，两行都允许自定义显示内容，
  默认文字 + 历史收益额，上下行均可自定义颜色」。据此：
  - 上行由「固定名称」升级为**四档可选**（`menubarHistoryTopMode`，默认 `label`）；
  - 第二行档位默认由 `cumPercent` 改为 `cumAmount`；
  - 新增第二行自定义色字段 `menubarHistoryBottomColor`；上行自定义色继续复用 `menubarGroupColors`；
  - 配色规则由「下行 signed 二分支」升级为「两行各自 `自定义色 > 涨跌色 > 兜底色`」；
  - 渲染层重构：`bottom_display` → `history_row_display`（单行通用）+ `day_pnl_display`（当日收益）
    + `rows_of`（按实例类型分派），`BottomDisplay` → `RowDisplay`；
  - 设置页「历史项」分区改为两行独立配置（名称输入框只在第一行选「名称」时展开），两行颜色各自一个开关 + 取色器。
- **2026-09-16 三次迭代（数值口径可选）**：用户问「历史收益额是包含今天的吗？」——答复：包含（口径是
  持有收益 = 最新市值 − 成本，`currNav` 取当日估值或当日确认净值；仅当数据源两者都拿不到时回落到
  最后披露日净值，此时不含今天）。同时发现一处**口径不对称**：盘中「当前持仓额」走
  `summary.totalAmount`（已公布净值口径），而「历史收益额」走含今日口径，两者并列会「对不上账」。
  用户拍板「加上今天最新的、以及昨天已确认的两种让用户去选」，据此：
  - 新增设置 **`menubarHistoryValuation`**（`latest` 默认 / `confirmed`），只作用于「历史」实例的
    三个数值档（收益额 / 涨跌幅 / 持仓额），不影响「当日收益」（它本来就是今 vs 昨的差）；
  - summary **双端各新增两个字段**（1:1 对齐）：
    - `totalAmountLatest` = 全部纳入总览持仓 @含今日市值（Σ `ovLive`）；
    - `totalCostedAmount` = **已录成本那部分**持仓 @已确认市值（Σ `ovAmount`，仅在 `overviewHasCost` 分支累加）。
    - ⚠️ 后者是**必需的**：持有收益只统计录入成本的持仓，若用 `totalAmount − totalCost` 反推，
      部分持仓未录成本时会把它们的市值误算成收益（虚高）。
  - 三档取数收口到 `menubar_common::history_values(summary, valuation)`：
    `latest` 直接复用 `total_cum_pnl(_percent)`（与原实现数值完全一致，零回归）；
    `confirmed` 用 `total_costed_amount − total_cost` 现场推算。
  - 未录成本（Rust 侧 `total_cost == Some(0.0)`）→ 收益两档 `None`（渲染层回落显示持仓额）；
    快照未就绪 → 三值全 `None`（占位符）。
  - 设置页新增「数值口径」分段控件（**最新** / **已确认**）。
  - **验证**：typecheck / build / guard:shim(295) / `cargo check --all-targets` /
    `cargo test --lib`（**34 passed**，新增 5 个口径单测）/ check:versions(1.6.2) 全绿；
    运行时 smoke **17/17 通过**（含"改其它设置后本字段不回落"与 summary 新字段的部分录成本场景，
    与 Rust 单测同场景同数值 → 双端对齐）。

- **2026-09-16 四次迭代（修复：「历史」第一行颜色不生效）**：用户报「历史第一行的颜色不生效，第二行的才
  生效」。读实测配置确认症状来源：`menubarHistoryBottomColor` 有值（第二行 OK），而 `menubarGroupColors`
  **恒为空对象** → 第一行色根本没落盘。根因是 `menubarGroupColors` 的 key 白名单散落三处，其中
  **`packages/ui/src/lib/fundOps.ts` 的 `updateSettings` 是手写白名单**（`'' || __overview__ || 现有分组名`）
  且**漏 `__history__`** → 写入层静默丢弃（typecheck 全过，只在运行时暴露）。
  同源问题还有一处：Rust `normalize_config` 的 `menubarGroupSides` 白名单同样漏 `__history__`
  （Windows 任务栏「历史」项左右停靠设置会被丢，尚未暴露）。据此：
  - `updateSettings` 的 `menubarGroupColors` 分支**改为直接调用 core 的 `normalizeMenubarGroupColors`**
    （消灭手写副本，单一实现，杜绝再次漂移）；注释写明「勿再手写本白名单」；
  - Rust `normalize_config` 的 `menubarGroupSides` 白名单补 `__history__`；
  - `menubarHiddenGroups` **保持不收** `__history__`——历史项显隐由 `menubarHistoryEnabled` 独立控制
    （关闭 = 销毁实例），写进隐藏表会让两条路径互相干扰。
  - 新增 3 个 Rust 单测固化「三张表对 `__history__` 的不同态度」（colors 收 / sides 收 / hidden 不收）；
  - 运行时 smoke **15/15 通过**（第一行色落盘、改其它设置后不回落、非法 hex 丢弃、未定义分组丢弃、
    停靠侧可写、分组增删不影响历史键、上一轮 valuation/topMode 不回归）。
  - **验证**：typecheck / build / guard:shim(295) / `cargo check --all-targets` /
    `cargo test --lib`（**37 passed**）/ check:versions(1.6.2) 全绿。
  - 教训：**集合类设置（map 型）的白名单必须只有一份实现**；`__history__` 这类固定 key 不是分组名，
    任何按「现有分组名」过滤的白名单都会把它们误伤。
