## 二、关键设计

### 1. 内联弹层（D1/D2）
- **编辑模式**（点列表行铅笔）：预填该分组「持有金额（= 分组市值）」与「持有收益（= 分组持有收益）」；分组可切换（该基金已有分组 + 全部持仓分组 + 未分组）。
- **新增模式**（列表底部「+ 添加持仓」）：基金代码 + 分组 + 金额 + 收益。
- 统一字段：**持有金额（当前市值）+ 持有收益** + 金额口径选择器（amountBasis，prev/today）。
- **只读回显**（实时派生）：持有份额 = 金额 ÷ 基准净值；成本单价 = (金额 − 收益) ÷ 份额；持有成本 = 金额 − 收益。
- 保存：编辑走 `updateFund`（传 amount/amountBasis/group + 派生 cost）；新增走 `createFund`（传 holdProfit 反推成本）。存储模型 `allocations`/`costs` 零改动。
- 「全部」tab 下多分组基金编辑默认取第一个已命名分组，避免误写进「未分组」。

### 2. 列表（D1/D3/D4）
- 5 列表格：基金（名称 + code·金额 + 编辑按钮）/ 当日收益 / 持有收益（+ℹ️）/ **持有成本**（第二行显示成本占金额比）/ 最新净值。
- 「持有收益」表头 ℹ️ Tooltip 与设置页「名词说明」区块共用 `HOLD_PROFIT_TERMS_NOTE` 文案。
- 保存成功 → `data.triggerRefresh()` → 列表立即反映（SW 重算 cache 后推送）。

### 3. 设置页编辑表格（§4.3）
- 可编辑列：持有金额、持有收益；只读派生列：持有份额、成本单价、持有成本。
- 预填：金额 = 份额 × 最新确认净值；收益 = 金额 − 成本（navMap 就绪后一次性回填，`initialized` 标记防覆盖）。
- 保存：份额 = 金额 ÷ 净值；成本单价 = (金额 − 收益) ÷ 份额；**收益留空 = 保留原成本单价**（不误清空）。
- 无净值（新基金/取数失败）的行保存时报错提示。

## 六、后续优化：编辑页金额口径选择器（2026-08-08，v1.2.41）

依据 `docs/编辑持仓页-spec.md` §6.1，为设置页「编辑持仓」表格补上金额口径选择器，与单只弹层（总 spec §7）完全对齐：

- **UI**：表格上方新增 SegmentedControl「金额口径」（昨日结算 / 今日结算），全局生效（编辑页定位是批量微调，逐行选口径负担大，故用全局而非 spec 字面的「列」）。
- **默认值**：navMeta 就绪后按「数据源是否已出今日净值」智能推断（有 → today，无 → prev），与弹层编辑模式的 percentSource 推断一致；用户手动切换后不再自动覆盖。
- **预填**：持有金额 = 份额 × `pickBasisNav(basis, meta).nav`（不再是写死最新净值）；切换口径时**未手动编辑（touched）的行重置重新预填**，保证「不改即保存份额不变」；用户已编辑的行保留输入。
- **保存**：`shares = round(amount / pickBasisNav(basis, meta).nav, 4)`；口径取不到净值（如 today 但今日未确认）→ pickBasisNav 抛错，报错信息自带「请改用 prev」建议。
- **只读派生列**：持有份额 / 成本单价 / 持有成本实时按当前口径基准净值派生，与保存结果一致（用户看到即保存后）。
- 数据结构：`navMap`（只存 netValue）→ `navMeta`（存完整 `ResolveFundResult`，含今/昨净值与日期）；`EditRow` 新增 `touched` 标记。
- 验证：`pnpm -r typecheck` 全过 + chrome build 成功（v1.2.41）。
